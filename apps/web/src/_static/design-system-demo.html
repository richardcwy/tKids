§ 11 — Rules worth keeping

Seven principles
that distinguish this
from a pile of components.

i
Two-layer color

Primitives describe what a color is. Semantic tokens describe what it does. Components only touch semantic. Dark mode is a remap, not an override.

ii
Two axes of size

uiSize and layoutSpace are independent. A dense table can live inside a roomy page. Density is the user-facing knob that moves both.

iii
Tokens are CSS, not JS

Initial state in HTML attributes. Runtime changes via setAttribute. No token context provider, no re-render cascade, no hydration mismatch.

iv
Spec.md is for why, not how

Specs explain principles so humans and AIs can reason about edge cases. Concrete pixels and conditional logic live in .tsx.

v
Props named for what, not where

startIcon: LucideIcon, not prefix: ReactNode. The name should tell you the type.

vi
Derive with calc()

When one value depends on another, write the dependency. Don't compute it once and forget the relationship.

vii
State via data-* attributes

data-invalid, data-state="open". CSS targets them with attribute selectors. No conditional classes for state.

§ 12 — Forbidden

What a spec quietly
prevents.

A good spec is enforceable by reading it. These are rules you can feel before you can articulate.

✗ Don't
Two primary buttons

Primary means "the recommended path." Two primaries force the user to pick between equal emphasis — the screen got harder, not easier.

✓ Do
One primary, one secondary

The primary is the recommended action. The secondary is escape or alternative. Hierarchy is clear in a glance.

✗ Don't
Placeholder as label

The placeholder vanishes the moment the user types — and then they have to clear the field to remember what it was for. Labels stay; placeholders hint.

✓ Do
Label + input + help

Three required slots. The label persists, the placeholder shows format, the help explains what the field is for. ARIA wiring is the wrapper's job.

Visible to your team.
✗ Don't
"Invalid" as an error

Useless. The user already knows it's wrong — they're staring at a red border. The error must say what is wrong AND how to fix it.

Invalid input
✓ Do
Specific, actionable

Tell the user what went wrong and what to do next. The error replaces help — they share a row, never appear together.

§ 13 — Reading path

Six files, in order.

01
src/globals.css
The keystone. Tailwind v4 @theme inline bridges CSS variables into utilities, keeping them reactive to runtime attribute changes.
02
tokens/color/primitives.css → semantic.css
Two layers of indirection. Read the spec next to them; it explains why primitives in component code is a bug.
03
tokens/uiSize/ & tokens/layoutSpace/
Two independent axes, one data-density knob. The density spec explains the tension between user abstraction and correct implementation.
04
components/Button/button.tsx
Every shadcn pattern in one file — cva, forwardRef, Slot for asChild, displayName.
05
components/TextField/text-field.tsx
Label + control + help/error. Invalid state via data-invalid. ARIA wiring is the wrapper's job.
06
patterns/toolbar/toolbar.stories.tsx
Composition rules, not new code. Includes a ✗ example — the spec prevents primary-in-toolbar by explaining the why.
