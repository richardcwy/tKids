# v1.3.0425 — Accounts foundation (Phase A)

**Released:** 2026-04-25
**Branch:** main
**Previous:** v1.3.0423

## What changed

This is the foundation cut for the v1.3 accounts work. Schema, auth wiring,
and oRPC middleware land now; the onboarding wizard, settings/profile pages,
and `<AuthGate>` UI ship in v1.3.0426+.

### Schema (`packages/db/src/schema/`)
- `user`:
  - `birth_year` is now nullable (OAuth signups don't carry it; onboarding fills it)
  - `onboarded_at` (timestamp_ms, nullable) — null = pending onboarding
  - `handle` (text, unique, nullable) — public profile slug
  - `display_name` (text, nullable) — user-chosen public name (separate from
    OAuth-provided `name`)
  - `locale` (text, default `'en'`, enum `en|zh-TW|ja|de`)
  - `bio` (text, nullable, ≤ 160 chars enforced at write-time later)
  - `avatar_style` (text, default `'shapes'`, enum `shapes|rings|bauhaus|beam|marble`)
    — DiceBear style variant; URL is always derived, no file storage
  - `avatar_seed` (text, nullable) — optional reshuffle salt
  - `email_notifications` (boolean, default true)
  - `deleted_at` (timestamp_ms, nullable) — for soft-delete (Phase C)
- `subscribe_audit.outcome` enum extended: `oauth_signup`, `onboarding_completed`,
  `account_deleted`
- New table `shipping_address` — schema lands now, surfaced when first merch
  product exists (no UI yet)
- New table `comment` with `target_type / target_id / status` indexed —
  schema lands now, UI ships in a future v1.3.x with moderation queue +
  18+ gate

### Auth (`packages/auth/src/index.ts`)
- `databaseHooks.user.create.before` is no longer a hard throw on missing
  consent. Form signup (carries `birthYear` + `over13Consent` inline) still
  validates strictly; OAuth signup creates with `onboardedAt = null` and
  defers consent capture to the onboarding flow.
- `socialProviders.google` wired in conditionally — only enabled when both
  `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are present in env, so dev
  environments without OAuth credentials don't break.
- `polar.createCustomerOnSignUp` flipped to `false` — Polar customer record
  creation moves to the onboarding completion procedure (Phase B), so we
  don't mint Polar customers for users who haven't passed the age gate.

### Env (`packages/env/src/server.ts`)
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` added (both default empty).
  Add real values to `apps/web/.env` for local dev and to Cloudflare Worker
  Secrets via Alchemy for production.

### oRPC (`packages/api/src/index.ts`)
- New `onboardedProcedure` middleware. `protectedProcedure` checks for any
  authed session; `onboardedProcedure` additionally requires `onboardedAt`
  set. Identity-required action endpoints (donate / comment / purchase /
  settings writes) will use `onboardedProcedure`. Throws
  `ONBOARDING_REQUIRED` when the user hasn't completed onboarding.

### Backfill (`scripts/backfill-onboarded-at.ts`)
- One-time idempotent script that sets `onboarded_at = created_at` for every
  existing user where `over_13_consent = 1 AND birth_year IS NOT NULL`. Run
  once after `bun run db:push` so existing fans don't get bounced to
  `/onboarding` when that page ships.

## Deploying this cut

1. Local dev: `bun run db:push` (syncs schema to local libSQL).
2. `bun run scripts/backfill-onboarded-at.ts` — backfill existing users.
3. Production: when ready, register the OAuth app in Google Cloud Console
   (redirect URI `https://tkids.tw/api/auth/callback/google`), set
   `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` as Cloudflare Worker
   Secrets, then `bun run db:push` against Turso production followed by the
   backfill script. The Better-Auth Google provider flips on automatically
   once both env values resolve.
